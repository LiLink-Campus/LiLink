# 服务端 API 连接路由

`SERVER_API_CONNECT_ADDRESS` 是可选的 Web 服务端配置，值必须为 API 源站的 IP 地址，不添加 `NEXT_PUBLIC_` 前缀。生产值在 Vercel 的 Production 环境维护，不写入 Git。

启用后，服务端的用户数据加载、公开数据缓存刷新和同源问卷保存改为直接连接指定源站。请求 URL、Host、TLS SNI 和证书校验仍使用 `NEXT_PUBLIC_API_BASE_URL` 的 HTTPS 域名；不允许跟随重定向或连接其他域名。浏览器公开 API 地址和 Cloudflare DNS 配置不变。每个进程最多复用 16 条连接，现有请求超时、API 登录校验和应用限流仍生效。

此路由不经过 Cloudflare 的 API 边缘规则，适用于可信的网站服务端到已有 API 源站的通信。问卷保存入口仍校验同源 Origin，服务端只转发已有用户会话到固定 API 路径。用户数据不进入共享缓存。不要将此配置用于用户提供的任意 URL，也不要关闭证书校验。

配置变更需重新部署 Web 才能生效。源站迁移时同步更新该值；删除此变量并重新部署即可恢复通过域名的常规连接。生产切换前应先验证候选部署的真实页面，并核对源站访问耗时和 Vercel 错误日志。

2026-09-22 的排查中，Cloudflare 路径的公开问卷请求测到约 3–11 秒；同时间源站本机约 60–70 毫秒。资料聚合请求在源站成功返回约 97 毫秒，前端仍触发超时。这证明慢请求不能仅归因于数据库查询，但不代表所有用户网络延迟均有相同原因。
