## 正在验证与停止条件

独立 Linux 生产镜像与真实限流压测尚未通过。压测库是新建合成数据项目 `patient-meadow-65557384` / `br-muddy-poetry-azax6deb`，0.25–2 CU，计算配额上限 28,800 CU 秒；独立 API 限制 2 CPU / 3.5 GiB，单次运行最多 130 分钟。GitHub runner 的机房与生产不同，网络时延需单列，不能冒充同区域生产容量。临时 Cloudflare Tunnel 与 DNS、GitHub 演练 secrets 在任务结束后清理。

Vercel 当前内置浏览器仍待用户登录。后续需精确 SHA 的全部 CI、隔离前后端链路、内置浏览器目标状态检查、压测实际完成量、生产停写备份与 staged production 验证。任何数据、权限或容量门槛失败均不开放生产。

恢复边界以第一笔新写入计算，包含维护期验收；之后保留新写入并优先前向修复。生产接受新写入前才适用停写备份 RPO=0。

## 压测发现与修复（候选仍在验证）

- 第一轮独立 Linux 的 500 人撮合计算选出了 250 对，但逐对写入触发默认 5 秒事务超时，HTTP 201 的 `preparedCycleIds` 为空。已改为两次批量插入，并保留事务内的准备状态锁和唯一约束；事务有 30 秒上限。
- 旧计算阻塞 API 事件循环约 2.9 秒。候选把同一套精确评分和 Blossom 求解移入单独 worker，最多一个计算运行、三个排队，120 秒超时，worker 堆上限 1.5 GiB。故障会返回错误并进入既有准备恢复流程。规则单测与真实线程结果一致性、故障后下一任务执行均通过。
- 本地完整计算（24 题、稠密候选）500 / 1,000 / 2,000 人分别约 1.0 / 4.6 / 28.5 秒，进程峰值 RSS 269 / 635 / 1,413 MiB，主线程最大事件循环延迟约 22 毫秒。此项不是数据库、Vercel 或生产吞吐证据。
- 独立 Linux 第二次低负载检查 2 次业务请求/秒、20 秒共 41 次迭代，39 次成功、2 次传输 EOF；P95 约 6,050 毫秒、无丢弃迭代、无 429。未通过发布阈值。GitHub runner 与新加坡 Neon 的跨区延迟及本地出口链路需要单列；等待同区域独立测试机后重测。
- `f36fe42` 的 CI 与 Browser E2E 成功，Storybook 失败暴露了测试自身的 VIP 刷新/160 ms 动画竞态。候选让 VIP 仅在指定阶段变化，同时验证刷新前后允许的当前题、回到原题后的可见性与透明度；用户中心 49 项故事测试通过。新候选的全部远端 CI 仍需等待。
- 工作流新增 500 / 1,000 / 2,000 人真实 API 撮合和揭晓，逐级核验预期周期、配对数、参与人唯一性、冻结资料、引荐数量和全量首页快照；不能把 201 当业务完成。
