# 秋季问卷全量重填与历史数据保留方案

> **文档归属**：遵循 [文档总纲](README.md)，配套 [发布计划](2026-09-20-autumn-release-plan.md) 与 [迁移审计](2026-09-20-questionnaire-migration-audit.md)。
> **状态**：2026-09-20 用户已授权一条龙实施；归档、新版隔离、完整准入和历史资料冻结已实现，独立 Neon 升级/恢复演练通过，生产尚未变更。最新证据见 [执行记录](2026-09-20-release-execution.md)。

## 1. 已确定的产品规则

按用户决定：“保留旧数据，新的问卷不迁移，全部用户需要重新填写。用户数据、最近三轮过往匹配等保留。”

- 旧问卷版本、题目、已提交答案、草稿及确认记录全部保留；不把它们转换、复制或自动回填到新问卷。
- 所有既有用户统一从新问卷开始，旧版本的已提交状态不能抵免新版填写。新用户同样填写新版。现有停用/未激活账号保持状态，不因这次更新自动激活。
- 账号侧的用户 ID、邮箱、密码散列、学校、昵称、联系方式及既有业务关联保留，用户可使用原账号登录。
- 问卷内资料与偏好全部重新填写，包括原来的出生日期、性别、自评、身高、体重、介绍、对方偏好、价值观题和新增生活习惯题。账号学校、昵称和联系方式仍取账号资料，不把“重填问卷”扩大成重建账号。
- 新问卷可以保存新草稿。完成当前新版的完整提交后，用户仍需明确报名新轮次；旧报名和旧问卷完成状态不自动续用。
- 未完成新问卷时仍可登录、查看账号和最近三轮历史匹配；仅限制新轮报名/撮合资格。
- 页面沿用最近三个已揭晓轮次，按揭晓时间倒序，覆盖匹配成功、未匹配、未参与三类状态。数据库中的更早历史也保留，本次不删除。
- 原始匹配关系、分数、已授权联系方式、举报屏蔽、优惠券、核销、邀请和审计记录保留。历史展示继续遵守既有授权、注销、举报和屏蔽规则，不重新发信、不重新撮合旧轮次。

“新问卷不迁移”在本方案中指不继承旧答案和完成状态。最终发布题库仍须固定、审查和版本化；不因此自动选用与线上分叉的 27 题 seed。

## 3. 建议的技术落地

### 3.1 独立保留旧答卷

新增受限访问的答卷归档存储，将本次切换前的每条活动答卷原样归档，至少包含：

- 原答卷 ID、用户 ID、原问卷版本 ID；
- 完整 answers 和 draftAnswers，保留空值、缺失字段及退役 key 的区别；
- 原提交时间、更新时间、确认版本/题目/硬字段签名；
- 归档时间、本次发布标识及来源，用于核验和追溯。

归档保留原始 JSON，不套用新版清洗器，不默认填国籍/语言，不换算颜值。以“发布标识 + 原答卷 ID”等唯一约束保证重复运行不会重复归档或覆盖原副本。账号外键关系和归档访问权限需与现有账号生命周期一致。

已知审计基数为 252 条答卷（242 已提交、10 草稿），只作为演练参考。正式停写后重新计数；归档数、内容校验和关联核对通过，才能切换活动答卷。备份与归档都需要，应用内归档不能替代可恢复备份。

### 3.2 建立独立的新版活动状态

推荐保留现有“一用户一条活动答卷”访问模式，以独立归档保存旧代数据，减少账号关系改造：

1. 创建并固定本次新版问卷/填写代次，不能仅根据“有新题”或“颜值可解析”判定是否需要重填。
2. 在同一受控切换中完成归档及核验，再初始化对应用户的新版活动答卷：无旧 answers、无旧草稿、无旧确认签名、无旧提交时间，关联新版。
3. 未填写用户没有归档也正常进入空白新问卷；切换逻辑幂等，重新执行不得抹掉用户在切换后已经填写的新草稿或新提交。
4. API 读取、前端初始化与自动保存按新版状态运行。学校、昵称、联系方式仍从账号表读取。
5. 保存、首页完成度、报名、撮合入口统一验证本次新版和全部必答项。拒绝旧客户端回传旧版本标识；仅靠缺失答案自然报错不足以建立版本隔离。

具体 schema、字段名和事务实现由后续实施确定；本文件没有提供可直接对生产运行的清空 SQL。对于迁移期间打开的旧浏览器页面，维护停写和版本校验应共同阻止旧页面覆盖新版活动状态。

### 3.3 保持历史匹配可读

当前历史卡片存在“旧匹配 + 当前问卷资料”的读取依赖，必须先解除：

- 保存旧问卷与既有匹配记录间可追溯的来源；历史卡片重建时，从适用的旧归档或受版本管理的历史展示资料读取介绍、性别等。
- 对确实没有当轮资料快照的历史记录，明确保存的是“本次切换前可见资料”，不得声称还原了当年匹配时的原始资料。
- 既有快照失效重建后，仍保持原轮次、配对、分数、参与结果和允许展示的资料。新问卷提交不重算旧匹配分数或替换历史答案。
- 联系方式继续依据既有引荐授权和授权时的联系方式记录读取；举报、屏蔽和注销仍动态生效，不能为保留历史而绕过可见性控制。
- 用户无需先重填新版即可进入“过往匹配记录”。最近三轮是系统最近三个 REVEALED 轮次，沿用当前实现；更早业务记录继续保留。

### 3.4 这次决定对前次审计的影响

不再实施旧答案到新问卷的颜值换算、合法软答案预填、71 份多选局部补填等继承方案。所有旧答案只归档，新问卷统一重新填写。

仍需处理：当前题库定义一致性、完整准入校验、当前新问卷的颜值最低分前后端一致性、VIP 权益与已保存新偏好的分离。旧偏好只保留在归档，不自动激活到新问卷；用户在新问卷填写后的权益变化不能导致其新偏好无意丢失。

## 4. 发布与验收

发布前先在隔离环境演练本方案，再按 [发布计划](2026-09-20-autumn-release-plan.md) 完成备份、停写、迁移、API/前端同步切换及回滚。新增实现会改变候选 SHA、迁移总数和测试基线，原“43 条总迁移 / 8 条待执行”仅为审计时状态，届时必须重算。

必须满足以下验收结果：

1. 切换前所有旧答卷和草稿都有原样归档，重复迁移不覆盖归档；账号数、用户 ID 和非问卷业务关联一致。
2. 旧提交、旧草稿、从未填写三类账号均进入空白新版；昵称、学校、联系方式和登录凭据保留。不能因缺新问卷强制退出或挡住历史页。
3. 新草稿保存、刷新、跨设备读取和完整提交均只影响新版活动答卷；旧归档内容保持不变。
4. 未填、缺任意必答、仅有旧提交、回传旧版本、携带旧会话的报名请求均不能进入新撮合池；新版填完后仍须明确报名。
5. 最近三轮成功/未匹配/未参与记录保持；迁移中失效快照重建后内容正确；旧轮次不会被新答案改写。
6. 原有联系方式权限、举报/屏蔽/注销限制有效；不补发历史邮件、不重复引荐、不重算旧匹配。
7. 回滚演练能恢复旧问卷、账号关联和历史页面；开放写入后的回滚必须保护新草稿与新提交。
8. Node.js + Playwright 在隔离环境覆盖桌面、移动视口和 Chromium/WebKit 的完整链路；另验证数据库原值/数量和 API 直接请求。
