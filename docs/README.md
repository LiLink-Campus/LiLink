# LiLink 设计与技术文档 (docs)

> **归档与规范说明**：本目录为 LiLink 平台产品需求（PRD）、核心机制、算法演进、前端视觉及埋点数据体系的单一可信源（SSOT）。文档结构与编写准则遵循仓库根目录 [AGENTS.md](../../AGENTS.md)。
> 
> **执行约定**：后续所有新需求、功能重构与版本迭代的 PRD，统一按照 **[PRD模板.md](./PRD模板.md)** 规范编写并归档。

---

## 一、业务定位与 SSOT 边界

- **定位**：系统化沉淀 LiLink 平台各业务域产品需求文档（PRD）、创新机制、撮合算法演进、交互与视觉体系、埋点资产的权威设计与实施规范。
- **凭据效力**：
  1. **研发与设计依据**：本目录下的现行 PRD/Spec 是产品研发、UI 设计与 QA 验收的唯一依据；未经 PRD 评审定稿的需求不得直接进入开发排期；
  2. **交付验收红线**：上线验收严格以 PRD 中的“验收标准清单（Checklist）”逐项核对；
  3. **历史方案封存**：过时、结项或被替代的方案统一归入 [archive/](./archive/README.md) 作为历史快照。

## 三、PRD 编写与归档规范

所有新功能 PRD 遵循**渐进式披露**原则，详细骨架与字段说明请直接查阅并复制 👉 **[PRD模板.md](./PRD模板.md)**。

### 1. 核心撰写要求

- **模板复制**：新建 PRD 时直接复制 `docs/PRD模板.md`，保留基本信息、目标与范围、核心需求、验收标准、待确认事项等核心章节；
- **三列表格化表达**：从第 3 章起，核心需求独立分章，强制采用 `| 功能名称 | 功能描述 | 原型截图 |` 表格；功能描述按“子功能行为 / 前置条件 / 异常与完成条件”结构化拆解；
- **量化验收清单**：验收标准须分解为可核对勾选的 `- [ ]` 检查项，且严格划分为“核心流程验收”与“异常与安全验收”；
- **未决事项闭环**：末尾明确记录 `[待确认问题 ｜ 负责人 ｜ 预计确认时间]`，定稿后闭环沉淀入正文。

### 2. 命名与归档规则

1. **命名规范**：单文档遵循 `YYYY-MM-DD-<topic>-prd.md`（如 `2026-09-11-cupid-wingman-prd.md`）或 `[产品名][版本]_PRD.md`；大型多文档需求建立独立子目录并在子目录内设立 `README.md` 父页面；
2. **顶部回溯链接**：文档顶部保留回溯父页面的相对路径：
   ```markdown
   > **文档归属**：本 PRD 遵循 [docs/README.md](./README.md) 规范归档。
   ```
3. **相对路径引用**：文档间交叉引用一律使用相对路径，跨领域引用指向对应分类目录的 `README.md`。
