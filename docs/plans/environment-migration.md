# 环境迁移与组织资产归属计划

> 文档归属：[计划](README.md)。

本页保留环境迁移和资产组织化的待确认选择；它不是当前资产、权限或生产状态清单。执行方法见 [环境重建与迁移](../guides/environment-migration.md)，当前部署契约见 [系统拓扑](../reference/topology.md)。具体账户、资源、连接和人员信息由受控资产清单维护。

## 目标与交付边界

接收方能够通过项目 docs 理解业务和运维，通过自己的组织资产独立发布、恢复、续费与处理告警。交付应覆盖代码历史、域名控制能力、获授权的完整业务数据、配置项清单、可复现验收与恢复方法；个人私钥、个人云/SaaS账户密码和旧环境文件不作为默认交付物。

迁移不应改变用户业务标识、密码 hash、历史关系与 migration 历史。更换认证或票据密钥对会话、待消费票据与调用方的影响需要在割接计划中明确。资产可转移还是需要重建由 provider 权限、组织归属和服务约束决定，不能按旧个人账户的便利性代替决策。

## 组织资产模型

| 资产 | 待采用的管理方式 | 完成证据 |
| --- | --- | --- |
| 安全邮箱与恢复渠道 | 组织拥有、可续任的安全邮箱作为恢复锚点，明确管理人与备用恢复路径 | 新负责人可恢复访问、收到安全/续费通知，MFA 与恢复材料受控保存 |
| 域名与 DNS | 组织拥有注册和边缘账户，成员使用可撤销权限 | 接收方可修改规则、续费和恢复旧路由 |
| 云主机与部署 | 组织项目/账单，成员个人 SSH 与最小权限；有独立救援入口 | 新执行人可发布与恢复，离任成员可单独撤权 |
| 数据库 | 组织拥有项目、服务 role、备份/PITR；不依赖离任个人凭据 | 完整性、隔离恢复演练和访问撤权验证 |
| Web、邮件、监控 | 组织拥有项目与发件身份，成员个人权限，单独部署/上传凭据 | 发布、实际收件、告警和 source maps 可由接收方验证 |

组织邮箱用于资产归属与恢复，不要求所有人共用一个登录密码。优先使用 provider 的组织/团队和成员角色；不支持成员权限时需另行确认凭据保管、MFA 与可审计的访问方式。人员变动时更新成员权限、签名/部署凭据和恢复联系方式，尽量通过撤权完成交接，减少整套环境重建。

## 执行前必须确认的决策

- 迁移哪些资产，哪些可转移所有权，哪些必须重建；域名继续使用还是变更，是否影响邮箱验证与 cookie。
- 目标预算、数据库区域/容量/连接限制、主机资源、日志保留、备份/PITR 与告警；旧容量数字不能直接作为新环境配置。
- 数据范围、个人信息访问、加密/传输、留存/删除期限，以及恢复目标的独立身份核验。
- 停机与恢复目标、最终停写方式、所有写入者清单、队列处理、增量数据与邮件外部副作用的回退策略。
- 候选 API/Web 版本与 migrations 的兼容组合，旧镜像/deployment 恢复入口和验收责任人。
- 哪些历史管理员、商户和运维人员继续有访问资格，如何建立新访问、轮换密钥与撤销旧角色。

确认后的选择写入任务或 ADR，并保留负责人、证据和退出条件。历史材料里关于日志、备份、外部探针、防火墙或运维账户的风险是旧时点观察，必须重核现场后才登记为当前缺口。

## 分阶段验收

1. 资产与权限准备：接收方验证组织控制、成员权限、恢复入口、账单与告警。
2. 隔离重建与恢复演练：固定版本，恢复完整数据，验证用户链路与实际收件，记录耗时和失败回退。
3. 正式停写与割接：最终备份、目标恢复、正式域名/会话验证，仅启用一个业务与后台写入方。
4. 观察与下线：确认新写入一致性、恢复能力和接收方签收，按授权处理旧资源、旧权限与备份。

每阶段以可验证证据推进；不能证明恢复、兼容或单写边界时暂停割接。公开记录只保留角色、行为断言与脱敏结果，凭据、私有连接配置和真实资产标识留在受控位置。
