# 邮件投递与跨窗恢复

> 文档归属：[现行参考](README.md)。

## 数据与调度边界

业务事务持久化 outbox；取得发送槽位后领取，SMTP 在事务外。活动窗口内每分钟扫描，窗口外仍有独立低频兜底；内联调用不会把兜底截止点向后延。默认十五分钟兜底对齐 UTC 每小时 00/15/30/45 分，与公开缓存空闲检查共用窗口；自定义间隔仍从上次兜底扫描起计算，不做墙上时钟对齐。既有扫描退避和活动窗口优先，对齐不延长恢复上限。数据库扫描失败采用有上限的指数退避；成功扫描恢复正常节奏。一个进程只有一个扫描/批次执行者，多实例通过数据库 CAS 竞争。

`BACKGROUND_JOBS_ENABLED=false` 禁止后台扫描，仍允许内联发送。`MAIL_DELIVERY_ENABLED=false` 和 `RELEASE_MAINTENANCE=true` 都禁止新发起 SMTP。退休提醒、无效验证码、不可用匹配或预算耗尽的可领取记录进入 EXHAUSTED，清除 nextAttemptAt。

验证码必须存在、未消费、未过期且仍是该邮箱/用途最新记录。匹配邮件继续复用 Match 锁、账号、举报、屏蔽和撤销检查。每次领取及 stale 回收都比较持久化 attempts/maxAttempts，成功领取增加一次预算。完成写回匹配 PROCESSING、领取时间和 attempts，不能覆盖撤销或后续租约。

成功领取是开始发送的边界；进入 SMTP 的消息无法召回，后续失效阻止重试与过时完成写回。SMTP 不提供 exactly-once：已收件但完成写回失败时，在剩余预算内仍可能重发。

## 恢复预算与资源

| 配置 | 默认 | 允许范围 | 语义 |
| --- | --- | --- | --- |
| OUTBOUND_EMAIL_IDLE_POLL_MS | 900000ms | 60000–3600000ms | F，空闲兜底间隔 |
| OUTBOUND_EMAIL_SCAN_BACKOFF_MAX_MS | 300000ms | 60000–900000ms | B，扫描故障退避上限 |
| OUTBOUND_EMAIL_DB_TIMEOUT_MS | 10000ms | 1000–30000ms | Q，邮件连接获取/租用总截止 |
| OUTBOUND_EMAIL_SMTP_TIMEOUT_MS | 30000ms | 1000–120000ms | S，SMTP 单次绝对截止 |
| OUTBOUND_EMAIL_SEND_WAIT_TIMEOUT_MS | 30000ms | 1000–120000ms | A，等待发送槽位截止 |

邮件使用独立 Prisma/pg 池，不改变其他 API 的数据库超时；池最多 `SMTP_SEND_CONCURRENCY + 1` 个连接。Q 到期销毁实际 pg 连接，并移出池。SMTP 到期关闭池并销毁实际 TCP sockets；同池其他在途发送也可能失败，继续遵守预算和租约。发送槽位到期移除等待项，未领取邮件留待下次扫描。

cron 粒度 C=60000ms。旧扫描/批次释放的上界 W 为 `5Q + A + S`，因为一次扫描、领取事务、完成写回、失败写回和状态同步分别有 DB 截止，所有排队项同时开始有界等待。默认 W=110000ms。保守扫描恢复界为 `T_scan <= max(F,B) + C + W + Q = 1080000ms`，另受运行环境调度误差影响；持续的进程停顿不属于健康调度前提。

送达界另依赖有限积压、类别、批量、并发、SMTP 截止及重试次数。扫描成功不能替代实际收件，也不能用 F+B 声称全部送达。

## 诊断与回滚

候选扫描复用自身结果记录采样时间、候选数量、是否被批量截断、最老候选年龄、最近成功扫描、连续失败开始时间、下一兜底和退避截止。候选包括尚未完成资格校验的记录，不代表完整队列长度；数据库扫描失败后样本为 UNKNOWN，不能显示为零。指标没有每 tick 附加查询；空闲空队列每 F 最多一次扫描（外部显式 flush 另计）。日志省略收件人、正文、验证码和 SMTP 原始异常文本。

邮件无需 schema migration。回滚代码会恢复旧的跨窗停扫缺陷；紧急回滚后应在授权运维范围内持续观察待办并安排恢复扫描。实际故障与收件验收见[隔离验收记录](../validation/mail-outbox-recovery-2026-10-06.md)。
