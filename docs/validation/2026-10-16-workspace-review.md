# 工作区审阅与文字券验收（2026-10-16）

> 文档归属：[验证记录](README.md)。现行规则见 [活动优惠券](../reference/coupons.md)。本页记录发布前工作区验收，生产状态以最终发布回执为准。

## 审阅范围与修复

审阅了商家状态退役、活动模板、文字券与互斥核销、后台用户资料分组、团队页及配套迁移。共享层保持状态与动态码语义，模板配置归活动模块，核销事务归核销模块；历史金额仍保留在实际核销记录中。

- 修复同组券状态误判：用户打开 A 券后，商家核销 B 券，A 的轮询原先会把 B 也显示为同组作废。现在只采用当前券的权威状态，再重新读取分组相关列表，不推断其他券谁被核销。
- 修复测试用户清理：新增 `CouponGroupRedemption` 的 Restrict 外键会阻止删除券与用户。清理事务先删除该用户的组使用记录，普通用户的券和互斥组配置保持不变。生产批量测试用户操作仍被禁止。
- 修复旧规则转文字时的金额格式：保留金额精度，去除 PostgreSQL 数值除法产生的多余末尾零；整数、分币及折扣上限使用精确文本断言。
- 更新既有 PostgreSQL 集成测试和 Storybook，移除对已退休字段、服务方法和页面入口的依赖。既有邮件并发测试保留页面联系方式一致性检查，邮件断言对齐已实施的登录后查看规则。
- 同步系统拓扑中的商家授权与直接核销说明，移除核销统计中的旧面值提示与 fixture 字段。

前两个行为问题均先通过既有 E2E 场景复现，再修复实现；没有新增单元测试。

## 可重复验收

前提为仓库锁定的 Node 24.20.0、npm 11.19.0、已安装依赖、本地 Docker daemon 与 Playwright 1.60.0 浏览器。业务数据仅在运行器生成的 disposable PostgreSQL / Mailpit 中创建，不使用开发或生产数据。

```sh
npm run test:ci:core
npm run test:ci:stories
node scripts/e2e/run.mjs coupon-groups.spec.ts admin-operations.spec.ts --grep 'text coupons use|legacy rules become|bulk test-user removal'
npm run docs:check
npm run docs:verify
```

针对性 E2E 为 5/5 PASS、0 skipped、0 flaky：Chromium 验证三项行为；分组核销场景额外覆盖桌面 WebKit 与移动 WebKit。原生 JSON/HTML 报告及截图在 `artifacts/e2e/6e31fc720ede/`，包括组使用唯一性、成功券与作废券的界面区别、历史金额保留、精确文字转换和测试用户清理边界。

Storybook 固定行为集合为 216/216 PASS；未被 test tag 选中的 4 个展示文件不属于必要行为用例。核心集合中的 API Jest 为 583/583 PASS、Web 行为测试为 110/110 PASS、PostgreSQL 集成为 198/198 PASS。完整浏览器集合终态与精确提交的 CI 结果以对应原生报告和最终发布回执为准；本地工作区证据的 `sourceDirty: true` 表示 SHA 仅为基点，不能替代最终提交的远端 CI。

## 视觉与证据边界

Codex 内置浏览器在 1280×900 与 390×844 检查运营概览、商家列表及展开账号、添加账号表单、活动配置及结果空态、用户资料分组、轮次管理、优惠券列表及动态码弹窗、商家直接核销输入、扫码缺失动态码提示和团队页面。优惠券的 560/880px、商家页的 640px 断点各检查前后 1px，9 个布局均没有文档横向溢出；390×844 动态码弹窗实际上下边界在视口内。截图和布局记录保存在 `artifacts/review-20261016/`。合成数据的视觉准备脚本同目录保存；会话需先用隔离运行器的 `--serve` 启动。

WebKit 是 Playwright 隔离引擎，不代表安装版 Safari 或真实 iOS。核销成功、互斥作废与重试等行为由固定回归及对应截图补充验证；内置浏览器定向视觉检查和自动化回归分别记录。

`docs:preview` 的一条既存 EVD001 位于历史性能记录的失败判据，人工复核为验收要求而非没有证据的实测结论，未改写历史文档。

## 发布要求

5 个待执行迁移包含删列与旧规则转文字，必须成对发布 Web/API。发布前保留旧镜像、Web deployment 和受控配置恢复点，对加密数据库备份进行隔离恢复及候选迁移演练。真实数据库只运行已审核迁移，不运行测试数据 seed 或核销；发布后检查实际 API/Web 提交、迁移终态、历史数据不变量和只读接口。

生产真实用户领券、扫码核销和邮件入箱不能由上述隔离结果或健康检查代替，未执行时必须明确记为 UNVERIFIED。
