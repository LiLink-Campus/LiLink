# 后台精简与自建埋点退役

本记录对应 2026-09-16 本地实现，尚未提交或部署。用户选择先精简后台和旧埋点，暂不接入 PostHog。

## 后台职责

- `/admin`：4 项平台概况、当前轮次、举报与人工匹配跟进、3 个常用入口。系统配置和测试工具默认折叠，原保存、生成和删除功能保留。
- 原“活跃用户”改称“正常账号”，实际口径仍为数据库中状态正常且未注销的账号，不声称是日活。
- `/admin/analytics`：导航及标题改为“运营统计”，保留基于业务表的学校与性别分布、每轮报名趋势、匹配结果明细。默认排除测试账号。
- 移除产品行为漏斗、事件总数、埋点活跃人数、不准确的优惠券浏览/核销比率，以及尚未接入的占位指标。没有加入空的 PostHog 页面。

## 代码与数据边界

删除自建浏览器曝光/点击采集助手及调用点、共享事件写入契约、`POST /v1/product-events`、`GET /v1/admin/analytics/product-funnels`、产品事件 producer、outbox 消费和补偿扫描。旧版本客户端调用已删除接口将得到 404；本次前端不再上报。

匹配揭晓事务继续保存引荐时间、冻结联系方式和写入通知邮件 outbox，但不再生成 ProductEventOutbox。优惠券核销继续保存 Redemption 和 AuditLog，不再写产品埋点。复制联系方式、兑换码展示、优惠券已读状态均保持业务功能。

保留 ReferralEvent、邀请归属、券领取/激活/核销记录、邮件 outbox、审计记录以及业务统计。这些支撑实际业务，不能用点击采集代替。Sentry 错误监控、Vercel Analytics 和 Speed Insights 本次未改动。

不修改或删除历史数据库表，不手动清空事件。`RetiredProductEventsService` 只保留原有每日 03:00、按 createdAt 删除超过 60 天 ProductEvent / ProductEventOutbox 的清理任务。历史 outbox 不再消费或补偿，会按同一保留期限自然清理。测试用户删除流程中清理其历史事件的代码仍保留。

## 以后接入 PostHog

[PostHog 官方产品分析文档](https://posthog.com/docs/product-analytics)支持事件趋势、漏斗、留存与路径分析。但自动采集点击不等于业务成功；注册成功、问卷提交、报名确认、匹配揭晓、核销成功仍需定义清楚的业务事件。

本次没有安装 SDK、配置项目 key、建立身份识别或向 PostHog 发送数据。在后续接入完成前，自建的产品行为事件停止采集，存在分析数据空窗；不会自动把旧库历史事件迁入 PostHog。后续需约定事件与去重口径、同意/隐私处理、账号注销，以及客户端行为和服务端结果的职责。不得把密码、邮箱、联系方式、问卷原文或举报内容当作默认事件属性。

- 100 个 shared 测试；69 个 API 单元测试；32 个后台及匹配页 Storybook 交互测试，另通过 7 个首页/优惠券页面交互测试。

- 实际后台 1440、390、900、901px 视口验证通过：无页面异常或横向溢出，设置展开、移动菜单及统计页导航正常。运营统计 3 个接口返回 200；旧采集与漏斗接口返回 404。截图和运行日志保存在 `/tmp/lilink-admin-refactor/`，不纳入 Git。
