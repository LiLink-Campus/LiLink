# 四项修复与旧流程清理

本次基于秋季分支现有未提交实现修复，不改变匹配算法、每轮主动报名、举报、匹配历史、优惠券和邀请的业务边界。数据库历史记录和后台审计继续保留。

## 四项问题

| 问题 | 修复及验收方式 |
| --- | --- |
| 注销后旧见面接口仍返回昵称和留言，旧提醒继续入队 | 移除 MeetupModule、11 条见面 API 和提醒任务；旧待发提醒及旧埋点队列置 EXHAUSTED，发送层再次拦截旧提醒。真实 AppModule 验证旧接口 404、无对应 cron，并确认历史留言仍存。 |
| 联系方式跨页面保存时，旧请求晚到覆盖新值 | User 新增 contactPreferencesRevision；GET 在一致快照内读取，PUT 同事务按 revision 条件更新、递增版本并保存联系方式，过期请求返回 409。前端卸载/超时取消请求，冲突保留草稿，用户重试时才获取新版本。冲突或保存结果不确定后废止本地保存基准，恢复初值也不能误报保存成功。 |
| 必填提示出现时，基本信息控件进入标签列 | 固定标签、控件、提示的网格行列，清除已被出生日期弹窗替换的旧三段选择样式；增加缺少必填资料的 Storybook 布局回归，检查控件宽度、提示相对位置。 |
| 自动揭晓后匹配漏斗仍统计手动申请 | 新增 match_introduction_queued，随联系方式冻结、揭晓邮件一起事务入队，按收件人幂等；新增 match_contact_copy_clicked。后台分开统计自动引荐收件人和浏览/复制行为，不把邮件入队写成送达或顺序转化率。补偿只识别同时具有双方 match-reveal 邮件的自动引荐。 |

## 清理范围与保留依据

- 后端：退役旧见面控制器、服务、DTO、提醒模板、定时任务、手动申请联系接口及邮件构造入口；移除 dashboard 见面状态收敛、旧用户反馈和申请时间字段；旧快照按现行字段读取，原 JSON 不改写。
- 前端：移除旧账号、名片、见面协商与反馈组件，以及其专属样式、Storybook、测试、API 客户端；清理旧首页待办展示字段、失效加载函数和未引用或已被覆盖的资料样式。
- 脚本与埋点：移除旧批量自动报名、见面演示脚本，历史演示仅保留匹配部分；清除旧见面/申请事件的生产与补偿逻辑及其模拟处理器。
- 保留：Prisma 历史表和字段、后台审计；旧页面地址保留重定向；历史已授权引荐邮件继续走现有队列和注销取消机制。已交给 SMTP 的邮件无法撤回。

## 迁移及发布边界

需应用 `20260913000000_contact_preferences_revision` 与 `20260913120000_retire_meetup_reminders`。新联系方式 PUT 必须包含 revision，旧浏览器页面需刷新。前后端应按同一版本更新；发布时应先停用旧 API worker 再执行退役迁移，避免旧进程继续创建已退役任务。

本次仅本地修改和验收，没有提交、推送或部署；本地检查不能替代最终提交的 CI。
