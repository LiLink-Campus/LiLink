## 并发与数据保留边界

注销的初始 User 锁使用 `FOR NO KEY UPDATE`，允许快照新建时的外键检查；真正修改邮箱发生在取得全部 Match 锁之后。此顺序避免「快照持 Match 等 User 外键锁，注销持 User 等 Match」的死锁。三个快照入口都经过真实 PostgreSQL 交错测试。

软注销保留原有业务记录、密码散列和审计规则。邮件取消仍兼容收件邮箱、`match-reveal` 与旧 `match-introduction` 去重键；没有根据历史注销邮箱全局禁邮，因此不会误伤该邮箱重新注册的新账号。已经进入 SMTP 的邮件仍无法撤回，但后续成功/失败回调不会把已撤销任务恢复成可重试状态。

PostgreSQL e2e 共用一个测试数据库且会修改 `max_registrations` 等全局配置，因此默认按单 worker 执行测试文件，避免相互覆盖配置。各测试内部的真实并发请求、数据库锁等待和发送队列交错仍保留。
