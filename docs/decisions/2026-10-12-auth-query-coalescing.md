# 恢复普通用户在途身份查询合并

> 文档归属：[设计决策](README.md)。

## 目标与边界

按用户要求恢复并发受保护请求的身份查询合并，接受共享在途旧查询的时间差。本决策覆盖[密码重置撤销账号旧会话](2026-10-06-user-session-revocation.md)中禁止跨请求合并及重置后新请求必须立即读取新状态的并发边界；版本字段、密码重置事务、无版本旧令牌策略 A 和三种角色隔离继续保留。

仅合并同一个 API 进程内、同一用户且同一 JWT 会话版本的进行中身份读取。查询成功或失败即删除，不设 TTL，不保留已完成授权结果。不同账号及不同版本独立读取；每个请求仍校验 JWT 类型、账号停用/注销和版本匹配。管理员、商家和密码登录接口不参与该合并。

## 接受的并发取舍

重置前已读取且尚未返回的旧状态可以被随后到达的同版本旧会话请求共享，这些请求可能继续读写。该窗口持续到该次身份查询结束；不承诺固定毫秒上限，也不中断已经通过 Guard 的请求。合并结束后的旧会话新请求重新读库并返回 401。新版本令牌不会等待或共享旧版本的查询。

同版本停用或注销的状态变化也可能在旧查询进行中时被共享，下一次独立查询重新验证。异常共享给本次等待者，但失败结果不缓存，后续请求可恢复。不把合并应用层调用次数直接等同于底层 SQL 次数，验收单独观察真实 SQL。没有证据说明恢复合并能解决数据库冷启动或 Cloudflare 线路故障。

## 实现前的失败方式与验收

- 同用户、同版本的交叠 HTTP 请求仍重复读取身份：使用真实 PostgreSQL，暂停第一次已读取结果，再发并发请求，确认只有一次身份读取及一次对应 SELECT。
- 查询结束仍复用结果：结束后重新发请求并变更停用状态，必须重新读库且返回 401。
- 失败结果留在合并状态：本次等待者得到失败，下一次请求成功，且重新查库。
- 不同账号互相阻塞或串用身份：一个账号暂停时，另一账号仍独立返回自己的身份。
- 新会话共享重置前状态：旧查询暂停，密码重置后新版本会话须独立成功；同版本旧会话可共享旧结果，待查询完成后重新请求须 401。
- 密码重置事务、旧密码并发登录、非法版本、停用/注销和内部字段响应回归：复用现有会话 HTTP + PostgreSQL 与浏览器路径。

测试先于实现调整。只用 runner 的 disposable loopback PostgreSQL/Mailpit 和合成账号，查询屏障与观测只在测试进程，生产不添加故障注入接口。

## 验证与回退

```sh
node scripts/e2e/run.mjs --api auth-query-coalescing.e2e-spec.ts auth-session-version.e2e-spec.ts
node scripts/e2e/run.mjs auth.spec.ts --project=chromium --project=mobile-webkit
```

回退仅移除在途查询合并，恢复逐请求身份读取；不删除或降低 sessionVersion，也不恢复无版本令牌。实际执行结果与工件由相应验收记录说明，PR 与部署分开报告。
