# 密码重置撤销账号旧会话

> 文档归属：[设计决策](README.md)。

## 目标与边界

对应 [issue #139](https://github.com/LiLink-Campus/LiLink/issues/139)：密码重置是账号被盗后的止损手段，成功响应后的新受保护请求不能继续使用旧用户 Cookie。已经通过 Guard 的在途请求可以完成；此方案不召回已完成读取，也不中断业务处理中写入。

## 采纳的设计

`User.sessionVersion` 是非空整数，新增和存量账号基线为 0。重置事务共同提交验证码消费、密码更新和版本原子递增。新 JWT 直接采用该事务返回的版本；事务失败三者一起回滚。

注册、登录、重置复用一个签发入口。登录的密码哈希与版本来自同一次账号读取；密码校验后只记录登录时间，不通过更新返回值或额外查询升级会话版本。旧密码并发登录可能获得旧版本令牌，但不能在重置提交后的新请求中继续有效。

Guard 先拒绝缺失、非整数、负数和类型不符的版本，再在每请求一次的账号读取中严格比对当前版本，继续检查停用与注销。移除跨请求 `pendingUserLoads` 合并，避免重置后发起的请求复用重置前已读取但尚未返回的状态。没有 TTL 账号缓存、授权结论缓存或生产故障注入接口。

版本属于内部撤销状态。`/auth/me` 保留既有字段，仅新增显式排除项；后台用户状态、资料、邀请额度更新也排除该字段。管理员和商家 Guard、Cookie 名称、会话 TTL 不变。

## 旧令牌迁移：策略 A

上线后所有缺少 `sessionVersion` 的普通用户 JWT 均返回 401，即使账号版本仍为 0。现有普通用户需要重新登录一次；不提供宽限期、基线放行或兼容策略开关。

## 发布与安全回滚

先执行数据库 migration，再启动版本签发与校验代码。迁移只增加默认 0 的列，因此旧进程仍可运行，但旧 Guard 仍接受已撤销会话。按[生产发布流程](../guides/production-release.md)核对实例版本和所有认证入口，切流后停止旧实例、等待退出并移除路由；仅当全部用户认证流量进入新实现时，才能宣布撤销保证生效。混用旧 Guard 的阶段不能视为完成。

回滚候选必须保留版本签发与校验以及数据库列。不得回退到不校验版本的旧代码，不得删除列或降低已递增的版本，否则旧 Cookie 会重新有效。候选不满足该条件时维持维护窗口，用前向修复恢复服务。

## 行为验收

先列出的失败方式包括旧 Cookie 继续读写、事务部分提交、旧密码登录升级版本、延迟读取被后续请求共享、缺版本基线被放行、停用/注销回归和内部字段泄漏。

复用浏览器注册与密码重置路径，并增加两个独立上下文、Mailpit 验证码、旧 Cookie 读写 401、返回登录页、新会话读写、新旧密码行为和响应字段断言。密码/Cookie/验证码不写入录制工件。隔离 HTTP + PostgreSQL E2E 用测试进程内 Prisma 查询扩展制造事务失败和同步屏障，生产代码没有测试后门。

```sh
npm run typecheck:api
node scripts/e2e/run.mjs --api auth-session-version.e2e-spec.ts
node scripts/e2e/run.mjs auth.spec.ts --project=chromium --project=mobile-webkit
```

运行前提为 Node 24、npm 11、Docker 与隔离 Chromium/WebKit。runner 创建一次性 loopback PostgreSQL、Mailpit、合成账号和临时密钥；工件位于 `artifacts/e2e/<run-id>/`。测试运行与 CI 分别报告，不把构建成功等同业务验收。
