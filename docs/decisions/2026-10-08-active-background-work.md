# 业务变化主动处理与低频恢复

> 文档归属：[设计决策](README.md)。

关联 [Issue #156](https://github.com/LiLink-Campus/LiLink/issues/156)。

## 目标与边界

正常业务提交后主动唤醒公开缓存通知；持久队列决定合并、租约和业务重试截止。通知确认同时建立可恢复的首页核验目标，核验服务自己管理到期运行。通知服务只发模块内信号，不反向依赖核验服务。定时器是加速器，数据库是事实来源。

通知与核验共用模块内调度策略：单执行者、提前唤醒、到期执行和独立扫描故障恢复。正常空闲落在 UTC 每小时 00/15/30/45 分；邮件默认兜底对齐这些时刻，自定义间隔保持原有语义。业务截止早于兜底时优先运行。轮次到期判断保持不变。

新增核验完成 revision 和结果字段，将最近通知与历史成功区分；迁移不将历史 hash 推定为完成。核验领取仍使用数据库 CAS。正常暂缓不扣减预算；相同内容修复不重置预算。旧执行者不能完成新目标。

缓存数据库操作使用有实际连接释放能力的有限截止，复用邮件已经采用的连接租用截止机制。数据库读取、领取、确认错误统一交给扫描故障策略，HTTP 错误才走业务退避。连接获取及租用各阶段有界；服务退出取消调度，停用和维护模式禁止新后台操作。

## 实现前的失败方式与行为验收

| 失败方式或边界 | 外部可观察契约与证据 |
| --- | --- |
| 注册、问卷提交、管理员冻结/学校归属/测试标记缺少唤醒 | 业务提交后在下一次十五分钟兜底前读取并安排持久任务；回滚不触发处理 |
| 五分钟门限、有效租约、领取竞争 | 自动保留并安排资格恢复时刻，恢复后六十秒内领取，无需新请求；暂缓不消耗预算 |
| 首次 SWR 旧页面、HTTP 故障 | 继续核验并最终展示正确内容；三十分钟接收门限与六次预算保持 |
| A → B → A、在途目标变更、确认后退出 | 完成记录绑定通知 revision；启动恢复待办；旧 token 不可完成新目标 |
| 数据库连接失败、查询锁阻塞、写回结果未知 | 状态 UNKNOWN，底层连接释放；恢复先读持久状态，不能假设操作失败 |
| 持续数据库故障及重复唤醒 | 失败确认后 60/120/240/300 秒重试；五次失败后独立十五分钟恢复，不重启快速预算 |
| 扫描恢复成功、业务预算耗尽、旧 Web | 分别恢复原待办、保留耗尽、标识 unsupported，不能冒充稳定或空队列 |
| 稳定空闲、漏唤醒、重启 | 至少两个完整十五分钟窗口；应用 SQL 间隔超过五分钟；漏唤醒可低频找回 |
| 邮件活动窗/内联发送、轮次到期 | Mailpit 实际收件与有效性，独立兜底不被饿死，保留原轮次揭晓时限 |
| 禁用、维护、退出 | 不新发起后台查询，取消残留定时器 |

优先复用既有 PostgreSQL、Mailpit、页面 E2E。新增行为覆盖先于实现，默认周期与加速故障证据分开记录。所有测试通过 `node scripts/e2e/run.mjs` 准备一次性基础设施，工件不保存 SQL、连接地址、邮件或用户数据。

## 取舍与回退

漏掉主动唤醒的未知任务最多约十五分钟才被发现；健康的已知任务不承担这段延迟。扫描故障退避预算独立于业务预算，耗尽后明确降级。正常空闲与数据库状态未知分别诊断。

十五分钟窗口只提供 Neon 休眠条件。真实流量、业务到期、每日清理、监控和其他连接仍可能唤醒数据库。代码验收不证明生产实际暂停或账单节省。部署后另以控制面和可比流量核对 compute 活跃时长与 CU-hours。

紧急回退可还原应用版本，保留 additive 字段；旧版本恢复每分钟扫描，会增加数据库活跃时间。数据库迁移不能删除旧字段或重置业务预算。此任务只提交 PR，不部署生产。
