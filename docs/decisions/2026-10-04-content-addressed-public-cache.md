# 公开缓存按展示内容核验与稳定追踪

> 文档归属：[设计决策](README.md)。日期：2026-10-04。状态：采纳；实际发布与验收结果另记于 records / validation。本决策补充[首页快照决策](2026-10-03-public-home-snapshot.md)的内容等价、发布核验与 Sentry 边界，保留小时 TTL 恢复路径。

## 问题与目标

当前首页失效 hash 包含轮次代号、报名截止时间等未展示字段。数据库产生 revision 不等于首页输出发生变化；等值排序不稳定也可能制造内容差异。另一方面，Sentry 随服务端重生生成的随机 trace metadata 会进入可缓存 HTML，使业务内容相同的重生仍产生不同输出。

通知确认只能证明接收端接受了 revision。Web 在持久领取后、执行失效前崩溃，或已失效页面暂未重新生成，都不能由 `deliveredHash` 推断实际首页已经发布对应内容。直接取消周期 TTL 会移除独立恢复机会。

目标是在现有 Browser → Vercel Web → API → PostgreSQL 路径内减少没有可见收益的 ISR 写入，同时保留缓存首屏、每次访问独立追踪和故障恢复。图片、JS、CSS、字体继续由 Vercel 提供；不新增服务、CDN、SSE、浏览器轮询或访问前同步核验。

## 选择

### 展示投影与发布标识

共享包拥有首页展示投影与协议版本。API 发送端和 Web 渲染端使用同一转换规则：只纳入真实展示的统计、社区图表与揭晓时间，不纳入未展示轮次字段或生成时间。投影是领域数据到页面视图的边界，其他公开 API 保持原有外部契约。

Web 为实际渲染快照输出带协议版本的稳定 fingerprint。该标识随缓存 HTML 发布，不在用户浏览器发起新请求，也不含用户身份、trace ID 或敏感配置。fingerprint 是内容身份；构建 SHA 在部署元数据和运行版本中独立核对，不放入内容标识。学校目录使用稳定的 `id` 决胜排序，避免等值行顺序抖动。

### 后台核验与有界修复

API 复用现有后台调度，每五分钟尝试核验实际首页。核验使用 PostgreSQL 持久 lease 和比较后写入，限制并发；预期 fingerprint 使用最近通知的 intended 展示内容，首次尚未知预期时才聚合当前公开数据。存在业务 pending 时不把未到发布时间的当前数据判定为发布错误，也不在每次空闲核验时重新聚合统计。实际 fingerprint 来自可读首页的标识；核验通过只记录该次实际观察到的内容。

读取必须限时、限大小、校验状态、协议与 fingerprint；重定向、错误页、缺少标识、格式不合法和不支持的混版均不能当作成功或擅自触发修复。发送端遇到缺少标识时仍可沿用固定 scope 的原有通知，不将其当作内容等价的充分证据。日志只保留脱敏错误类别与 scope，不输出页面正文、网络配置或凭据。

发现内容不一致时，只有不存在业务 pending、持久领取距上次至少三十分钟、当前状态未熔断且 lease 仍有效，才能比较后增加一条修复 revision。修复进入既有 dispatcher 和接收端门限；不直接改写首页，也不绕过 persistent claim。并发业务变化始终保留新 revision，过期核验或发送 worker 不得覆盖新状态。

发送端只有在当前展示 hash 与已投递 hash 相同，且已核验实际页面发布对应内容时，才能省略失效并确认等价 revision。历史的 `verifiedHash` 不是永久正确的证明，核验与发送必须保留并发和时点边界。收到 HTTP 成功、持久领取成功或 dispatcher 确认，均不能替代页面内容核验。

核验领取即消耗有界尝试，异常退出也不丢失已消费预算；每个预期内容最多六次失败或有效修复后熔断，不通过不断生成修复 revision 重置故障预算。正常门限延期和业务 pending 不消费故障次数；未支持标识的混版不产生修复，也不将其记录为核验成功。新的预期展示内容或实际核验成功可以重新进入验证与通知。熔断后保留独立 TTL 路径，故障原因和未收敛状态仍可诊断。

### 保留小时 TTL

首页 Full Route Cache 与其 Data Cache 继续使用小时 TTL。它覆盖调度停止、配置故障、领取后进程崩溃和核验熔断后的访问恢复机会；实际恢复仍依赖访问及上游可读，不承诺固定恢复时限。

业务内容稳定且 HTML 不再包含随机追踪元数据时，周期重生可得到相同输出。停止周期 render 或 Function invocation 与减少 ISR Writes 是不同目标，不能用“减少重生次数”证明账单下降。取消 TTL 会减少一种计算路径，却失去独立恢复能力，因此本轮不取消 TTL。

### Sentry 追踪边界

公开 ISR 页面的缓存 HTML 不输出 `sentry-trace`、`baggage`。浏览器在每次真实访问时独立创建 pageload trace；服务器重新生成缓存页面仍创建并上报其自身 trace。不能将 trace ID 固定或复用给多个用户与请求。

实际动态 SSR 页面继续输出本次请求的追踪元数据，使服务端与浏览器 trace 可关联。页面分类必须由实际渲染路径确定，不能以全局关闭 metadata 的方式破坏动态 SSR 关联。

错误事件、Replay、source maps、浏览器到 API 的追踪继续启用。公开 ISR 浏览器 trace 不再与某次缓存重生的服务端 trace 关联，这是内容缓存边界的明确选择。SDK 配置与实测必须证明独立 pageload、动态 SSR 关联和追踪传播，不以 DSN 存在或构建成功代替。

## 权衡与限制

后台核验增加低频服务器读取和两行缓存状态的持久写入，不增加用户访问路径的请求或计算。读取缓存标识可能触发既有 TTL 的重生；保留失败记录和限流，避免把核验自身变成无界重生源。

单次 HTTP 读取只能证明所访问 Vercel 边缘的内容；不证明全球同时收敛。页面发布的短暂异步窗口不应绕过三十分钟领取门限反复失效。当前 API 单实例公开内存缓存前提保持不变，扩容仍须单独解决多实例同步。

fingerprint 一致证明投影相同，不证明整份 HTML、RSC 或压缩计费大小相同。Sentry、框架输出及其他随机源仍须实际字节验收。减少 HTML/RSC 重复内容仅在不改变用户可见状态并测得压缩计费大小减少时有预算意义，本轮不为估算收益增加页面请求或改变交互。

## 发布与回滚

新增核验字段通过 additive migration 保留旧 API/Web 兼容。先保留当前 API 镜像、Web deployment、受控配置身份和恢复入口，再发布迁移及新 API，随后发布匹配协议的新 Web。发布期间旧 Web 缺少核验标识时走安全失败和既有 TTL，不以缺标识制造修复风暴。已有 HMAC 密钥、通知 URL、后台任务开关和生产拓扑继续沿用。

迁移通过生产入口执行；runtime 配置继续使用 Docker `api_env`，Sentry source maps 上传凭据继续使用 BuildKit secret。凭据、真实用户记录和数据库连接信息不进入 Git、日志或验收工件。

回滚恢复已核验的 API/Web 兼容组合及受控配置，保留 additive 字段，不做破坏性逆向迁移。旧版本继续接受保留后的数据库结构；旧 Web 的 metadata 策略恢复时可能恢复原有 ISR 写入风险，应单独记录。

## 验收

实施前明确失败方式，再通过 disposable PostgreSQL/Mailpit 与合成账号的真实 E2E 验证：未展示字段变化不重写页面、显示字段变化收敛、等值排序稳定、同内容重生字节稳定、重复/并发/重启通知去重、领取后崩溃被修复、核验失败有界、并发 revision 不丢失、过期 worker 不覆盖状态。

Sentry 验收分别检查公开 ISR HTML 无随机 metadata、两次真实访问 trace 不同、动态 SSR metadata 对应当前请求，以及错误、Replay 和浏览器/API 追踪仍按既有策略运行。性能对照与桌面/移动和 Chromium/WebKit 用户路径证据证明实际影响，不能用 HTTP 200 代替用户可见断言。

工件记录命令、隔离环境、数据前提、候选 SHA、逐项断言和必要脱敏证据。生产只做已授权的只读用户路径和版本核验；部署后 Vercel ISR Writes 增量与完整账期用量另行实测，不能把本地文件写入、保守模型或 render 次数换算成生产账单。CI 按最终精确提交核验，完整检查与发布规则见[生产发布](../guides/production-release.md)。
