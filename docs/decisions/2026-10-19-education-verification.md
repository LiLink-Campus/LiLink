# 普通邮箱开放注册与教育身份分离

> 文档归属：[设计决策](README.md)。现行契约见[账户参考](../reference/account.md)与[匹配参考](../reference/matching.md)。

## 背景与选择

普通邮箱原先须先获得邀请码，学校归属同时承担注册门槛与匹配条件。开放注册后，邮箱、学校资料、教育认证和 VIP 权益分别具有独立含义。所有邮箱仍须验证持有权；普通用户可不填写学校，也可自行选择学校，但自行选择不授予教育身份。

用户确认保留已有账号的教育身份。迁移将未注销的已有账号标为 LEGACY，保留原邀请额度；学校邮箱持有权不作历史重建。旧账号中可识别的学校邮箱占用独立教育邮箱唯一位。新账号默认为普通用户；通过当前允许注册学校的邮箱注册时，直接记录 SCHOOL_EMAIL。

## 领域与数据边界

`User.email` 仍是登录和默认联系邮箱。`educationVerifiedAt` 和 `educationVerificationMethod` 是教育身份依据，学校 ID 或邮箱外形都不能替代它们。`educationEmail` 仅用于占用已认证邮箱，不进入对方匹配资料；验证码以 `education:<userId>` 为用途，不能用于其他账号或注册、密码重置。

普通用户可在用户中心通过真实邀请码或教育邮箱升级。邀请码使用现有邀请额度，认证事务锁定双方账号后原子扣减；无效、停用、已注销、未教育认证、自邀和无剩余额度均拒绝。重复认证和并发重复提交只成功一次扣减。邀请认证不恢复被邀请用户的邀请额度，沿用原来普通邮箱受邀账号不扩散额度的边界；教育邮箱认证至少获得 3 个名额，保留管理员设置的更高值。

教育邮箱认证保留原账号、登录邮箱、问卷和报名。认证与注册使用同一邮箱事务锁，跨登录邮箱与教育邮箱两列检查占用，防止一份邮箱凭据绑定两个账号。注销释放教育邮箱唯一位，并消费本账号未使用的教育验证码。

没有学校时，由服务端在匹配协议中注入 `NO_SCHOOL_ID`，数据库不创建虚构学校，客户端不能凭答案覆盖账号学校。报名、问卷保存、候选过滤、预演和正式计算使用相同含义。

## 匹配与展示时点

优化目标为有效 VIP 人数、连续至少两次落空人数、教育用户人数、总匹配人数、契合度及原有小幅加分。每层权重超过整池低层目标的最大总贡献，层级与求解器的权重、对偶变量统一使用 BigInt；顶点编号仍使用 Number。不能用 Number 整池上界限制匹配规模：该方案会把当前问卷的容量降至 549 人，导致既有 2000 人发布演练失败。

仅在求解的最低层，将每条边的原始契合分按百万分之一四舍五入为整数，原有加分按同一倍率缩放；低于此粒度的差异视作相同。展示契合分仍沿用原始 Number 计算与一位小数归一化，不受此量化改变。原分必须有限、非负且缩放后为安全整数，否则明确失败；较高层人数目标通过 BigInt 精确保证，不受池规模或最低层小数舍入影响。复用同一 vendored Blossom，通过数值域常量支持原有 Number 对照，不新增第二套求解器或依赖。性别、身高、意向、有效高级筛选、拉黑及历史配对约束不被优先级绕过。

准备阶段在 `MatchParticipant.profileSnapshot` 冻结 VIP 和教育状态；结果页与历史详情只读取该轮记录，快照重建、之后升级或 VIP 到期均不改写它。旧轮次没有这两项记录时显示“该轮未记录身份信息”，不使用当前身份猜测历史状态。受限匹配继续隐藏全部对方资料。

## 发布与回滚

先执行迁移，再发布依赖新字段的 API 与 Web。迁移不会重新报名或重新计算已准备的匹配。生产操作另须遵守项目发布授权和备份要求，本决策不授权上线。

回滚优先回退应用版本并保留新增字段及已完成认证记录。旧版本恢复普通邮箱注册门槛，同时会把新普通账号误当作原有校园账号处理，因此不能只回退 Web 后声称教育标志仍可信；应同时暂停新认证入口、核对旧版本匹配资格契约，必要时停开新轮次。不要删除已认证记录或回滚数据库字段以掩盖状态。
